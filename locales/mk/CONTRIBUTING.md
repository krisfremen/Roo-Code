# Придонесување кон Roo Code

Roo Code е проект движен од заедницата и ние длабоко ги ценеме секој придонес. За да ја поедноставиме соработката, работиме на основа [Issue-First](#issue-first-пристап), што значи дека сите [Pull Request-и (PR-ови)](#поднесување-на-pull-request) мора прво да бидат поврзани со GitHub Issue. Ве молиме внимателно да го прегледате ова упатство.

## Пред да придонесете

### 1. Кодекс на однесување

Сите придонесувачи мора да се придржуваат кон нашиот [Кодекс на однесување](./CODE_OF_CONDUCT.md).

### 2. Патокарта на проектот

Нашата патокарта го води правецот на проектот. Усогласете ги вашите придонеси со овие клучни цели:

### Доверливост на прво место

- Обезбедете дека уредувањето на разлики и извршувањето на команди се стабилно доверливи.
- Намалете ги триењето точките што ги одвраќаат корисниците од редовна употреба.
- Гарантирајте мазно функционирање во сите локали и платформи.
- Проширете ја цврстата поддршка за широк спектар на AI провајдери и модели.

### Подобрено корисничко искуство

- Поедноставете го UI/UX за јасност и интуитивност.
- Континуирано подобрувајте го работниот тек за да ги исполните високите очекувања што ги имаат програмерите за алатки за секојдневна употреба.

### Водство во перформанси на агенти

- Воспоставете сеопфатни мерила за евалуација за да ја измерите продуктивноста во реалниот свет.
- Направете го лесно за секого да може лесно да ги извршува и толкува овие евалуации.
- Испорачајте подобрувања што покажуваат јасно зголемување во скоровите од евалуациите.

Споменете го усогласувањето со овие области во вашите PR-ови.

### 3. Придружете се кон заедницата на Roo Code

- **Основно:** Придружете се на нашиот [Discord](https://discord.gg/roocode) и пратете DM на **Hannes Rudolph (`hrudolph`)**.
- **Алтернативно:** Искусни придонесувачи можат директно да се вклучуваат преку [GitHub Projects](https://github.com/orgs/RooCodeInc/projects/1).

## Наоѓање и планирање на вашиот придонес

### Типови на придонеси

- **Поправки на грешки:** Решавање на проблеми во кодот.
- **Нови функционалности:** Додавање на функционалност.
- **Документација:** Подобрување на упатства и јасност.

### Issue-First пристап

Сите придонеси мора да започнат со GitHub Issue.

- **Проверете постоечки прашања**: Пребарајте во [GitHub Issues](https://github.com/RooCodeInc/Roo-Code/issues).
- **Создадете прашање**: Користете соодветни шаблони:
    - **Грешки:** "Bug Report" шаблон.
    - **Функционалности:** "Detailed Feature Proposal" шаблон. Потребно е одобрување пред да започнете.
- **Земете прашања**: Коментирајте и чекајте официјално доделување.

**PR-ови без одобрени прашања може да бидат затворени.**

### Одлучување на што да работите

- Проверете го [GitHub Project](https://github.com/orgs/RooCodeInc/projects/1) за недоделени "Good First Issues."
- За документи, посетете [Roo Code Docs](https://github.com/RooCodeInc/Roo-Code-Docs).

### Пријавување грешки

- Прво проверете за постоечки извештаи.
- Создавајте нови грешки користејќи го ["Bug Report" шаблонот](https://github.com/RooCodeInc/Roo-Code/issues/new/choose).
- **Безбедносни прашања**: Пријавете приватно преку [безбедносни советувања](https://github.com/RooCodeInc/Roo-Code/security/advisories/new).

## Процес на развој и поднесување

### Поставување на развојната околина

1. **Fork & Clone:**

```
git clone https://github.com/YOUR_USERNAME/Roo-Code.git
```

2. **Инсталирање зависности:**

```
pnpm install
```

3. **Дебагирање:** Отворете со VS Code (`F5`).

### Упатства за пишување код

- Еден фокусиран PR по функционалност или поправка.
- Следете ги ESLint и TypeScript најдобрите практики.
- Пишувајте јасни, описни commit-и што се однесуваат на прашањата (пр., `Fixes #123`).
- Обезбедете темелно тестирање (`npm test`).
- Направете rebase на најновата `main` гранка пред поднесување.

### Поднесување на Pull Request

- Започнете како **Draft PR** ако барате рана повратна информација.
- Јасно опишете ги вашите промени следејќи го Pull Request шаблонот.
- Обезбедете скриншотови/видеа за UI промени.
- Назначете дали се потребни ажурирања на документацијата.

### Политика за Pull Request

- Мора да се однесуваат на претходно одобрени, доделени прашања.
- PR-ови без придржување кон политиката може да бидат затворени.
- PR-овите треба да ги поминат CI тестовите, да се усогласат со патокартата и да имаат јасна документација.

### Процес на ревизија

- **Дневна тријажа:** Брзи проверки од одржувачите.
- **Неделна длабинска ревизија:** Сеопфатна проценка.
- **Итерирајте брзо** врз основа на повратните информации.

## Правни прашања

Со придонесувањето, се согласувате дека вашите придонеси ќе бидат лиценцирани под Apache 2.0 лиценцата, конзистентно со лиценцирањето на Roo Code.
